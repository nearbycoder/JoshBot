# Reading paths

Implemented locally, **unregistered and not deployed**; parent integration and independent review remain required. This feature allocates whole readings in stable topological/insertion order. Shared unread prerequisite closure is counted once within an explicit minute budget. The allocator is greedy, not a global optimizer. Oversized readings are deferred with a reason, never partially allocated. Reading completion is a user report, not mastery.

Start `/nobo-help agent reading-path create Learn queue basics`. Add `item PATH add Queue primer | 15 | Saved article` and `item PATH add Retry design | 20 | Engineering note`, then `requires PATH RETRIES | PRIMER`. `route PATH | 25` recommends the 15-minute primer and defers the 20-minute retry article because ten minutes remain. `read PATH PRIMER` records the report; the next route can allocate the retry article. No context calls occur in this pasted-only workflow.

`edit PATH | GOAL`, `item ... edit`, and `requires-edit` edit accepted fields. Missing prerequisites, duplicates, self-dependencies and cycles reject atomically. Changed item title/source, prerequisite edits/removals, bookmark attach/replacement/removal, or `unread PATH ITEM confirm` clear affected completion reports and downstream reports. Minutes-only edits retain reports about unchanged material. Changing the goal does not imply achieving it. `remove PATH item|edge|attachment CHILD_ID confirm` removes explicit input; item removal also removes incident edges and its bookmark snapshot. Help provides exact syntax and pipe/backslash escaping.

Optional `bookmarks PATH [QUERY]` reads only owned bookmark metadata, once, with a complete 100-item adapter bound. `bookmarks PATH --source SOURCE_ID` retrieves full adapter text/metadata. Every page carries both path revision and source-set fingerprint; changes require page 1. Titles are labeled previews in the list, while URLs remain complete. There is no article fetching, arbitrary workspace/channel/artifact source, read-later import, model or web search.

`attach PATH ITEM | SOURCE_ID | SOURCE_FINGERPRINT | PATH_REVISION` rereads bookmarks once and rejects stale, absent or invalid selections. `attach-edit PATH ATTACHMENT | ITEM | SOURCE_ID | SOURCE_FINGERPRINT | PATH_REVISION` replaces a selection. One complete snapshot per reading, ten total, at most 10,000 retained source-text bytes. Oversized snapshots reject without clipping. Shared `captureEvidence` retains exact references, source dates, safe HTTP(S) URLs, coverage/truncation and selected meaningful metadata (`source`, `createdAt`, `url`, `note`, `read`). Query order, escaping and fragments remain intact. Credential-bearing URLs, invalid URI escapes and ambiguous backslash/quote/angle-bracket URLs cannot be attached. Adapter provenance must identify the owned toolbox bookmark source. Bookmark read flags do not mark this reading complete.

`show`, `route` and `export` describe historical snapshots; only explicit `bookmarks` checks current availability, reporting stale/absent or unchanged within adapter coverage. Absence is not proof of global deletion. Existing snapshots remain retrievable after source revocation. Attachment capture time is separate from source time. URLs remain inert text.

`list [page N]`, `show PATH [page N rev R]`, `export PATH`, and `delete PATH confirm` cover complete retrieval and cleanup. Show/route continuations bind originating revision and exact minute budget; copy returned commands. Complete export JSON includes its envelope and stays within 24,576 UTF-8 bytes. Every retained field, source URL and annotation is available; no runtime truncation is used.

Strict schema version 1, canonical UUIDv4 IDs, ten paths, 24 readings/48 prerequisite edges and ten bookmark snapshots each. Goal/title 160 UTF-8 bytes, source label 200; reading minutes 1–1,440, route budget 1–10,080. State cap 49,152 bytes, content admission 32,768. Admission projects every completion timestamp plus maximum revision width into both state and per-record export caps. Read/unread and confirmed removals remain possible above the content threshold while retaining hard/remaining-lifecycle bounds. Byte limits may bind first. No expiry, eviction, history or global cache.

All mutation targets capture revision before source work/CAS and check every retry, including read, prerequisite changes, attachment selection and removal. Same-record contention rejects; unrelated-path edits retry safely. Corrupt state is preserved even by confirmed delete. Per invocation: zero generation/search, one context read, eight store reads/four updates, with separate 32 CAS attempts. Graph traversals use bounded visited sets over at most 24 nodes/48 edges.

Real runtime/store tests cover the catalog route, stable shared closure, cycles/dangling dependencies, completion invalidation, production bookmark adapter with fake backend at 100 sources, complete exact 2,048-byte URL retrieval, ten snapshots totaling exactly 10,000 source-text bytes with replacement/removal, stale/revoked/unsafe selections, source-text quotas, maximum graph retrieval/revision pages, strict boolean corruption, tenant isolation, actual CAS conflicts, deferred selection/deletion and Unicode/escaping completion lifecycle beyond content admission. Run `node --import tsx --test --test-concurrency=1 tests/agent-reading-path.test.ts` with Node 24. These checks do not establish live Slack delivery, provider behavior, Redis performance or deployment.

A readable, fully schema-valid legacy aggregate can exceed current admission quotas. Confirmed whole-root deletion checks the exact intended record on every CAS retry and removes only that root; repeated deletion recovers space even while remaining roots exceed quota. Remaining records and their independent lifecycle reservations are unchanged. Creation, editing, child removal and lifecycle updates keep their existing quota checks. Malformed data is preserved for scoped operator recovery, never reset or evicted. Tests simulate legacy aggregates by cloning real-command roots with unique IDs; normal admission does not create those fixtures.

Pure command, schema, quota, pagination and evidence validation failures keep their actionable guidance. Unexpected backend/provider diagnostics are never returned. A storage failure directs inspection before retry because a dispatched save might have completed; it does not promise rollback. Source-read failures preserve saved snapshots and retain typed capacity guidance. Cancellation, deadlines and runtime corruption/budget diagnoses remain runtime-owned.
