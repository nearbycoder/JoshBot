# Audience brief

Implemented and registered; [release/deployment status is tracked in PR #59](https://github.com/nearbycoder/JoshBot/pull/59). See the [grouped guide index](README.md#find-a-feature) and [implementation/evidence record](../personal-agent-50-release.md).

Keep canonical facts separate from audience-specific variants. Deterministic rendering preserves exact fact text, includes every required fact or reports overflow, and exposes coverage for every retained fact. Each audience has its own stated needs, word budget and explicit requirements. No messages are sent.

Start: `/nobo-help agent audience-brief create Pilot update`. Replace `ID`, `FACT` and `AUDIENCE` with returned IDs. Commands follow `/nobo-help agent audience-brief`:

- `fact ID add TEXT | required/important/optional`, `fact ID edit FACT | TEXT | required/important/optional`, `fact ID remove FACT confirm`. Confirmed removal also removes that fact's requirement links.
- `audience ID add NAME | NEEDS | WORDS`, `audience ID edit AUDIENCE | NAME | NEEDS | WORDS`, `audience ID remove AUDIENCE confirm`.
- `require ID AUDIENCE | FACT`, `unrequire ID AUDIENCE | FACT confirm`. Removing an audience-specific requirement does not override a fact's global required importance.
- `lead ID | TEXT`, `ask ID | TEXT`, `edit ID | title/lead/ask | TEXT`, `clear ID FIELD confirm`.
- `render ID AUDIENCE [page [rev REV]]` returns the unsent variant and coverage matrix. `polish ID AUDIENCE` optionally requests one unsaved finite composition, with exact facts and attributions.
- `list [page]`, `show ID [page [rev REV]]`, `export ID`, `delete ID confirm` retrieve/remove complete private records. Without confirmation, deletion only returns its exact confirmation command.

Words are whitespace-separated tokens in lead, ask and fact text; labels/IDs/coverage do not consume the content budget. This is a disclosed convention, not linguistic segmentation. Audiences accept 20–1000 words. Global and audience-specific required facts plus lead/ask are mandatory. If they cannot fit, no complete variant is produced and no polish call starts. Otherwise optional facts are selected by important before optional, then distinct lowercase Unicode word overlap with audience needs, then stable entered order. Whole facts are included only if they fit. This bounded lexical heuristic is not a semantic relevance or truth guarantee; every omission is visible in coverage.

Canonical text is never changed by render/polish. Variants are unsaved and labeled with the canonical revision, so there are no stored variants to become stale after edits. An explicit fact edit replaces that canonical field, increments revision and discards any pending older narrative; there is no hidden history. Show/export always retrieve current original inputs, not rewritten variants.

Polish uses stricter mandatory selection than deterministic render: every required or important fact, every audience-specific requirement, and the complete lead/ask must fit. Only facts explicitly marked optional and not audience-required may be omitted for the word budget; the output coverage matrix identifies each omission. Selection and fixed order are computed locally, never delegated to the model. If mandatory content exceeds the budget, increase that budget or explicitly edit the inputs/importance; no generation starts and nothing is silently dropped. Since all selected text is copied exactly, its whitespace content-word count cannot change. Display labels, coverage and finite nonfactual framing are excluded, just as headings are excluded in deterministic render.

Polish sends the selected facts (including attribution as part of exact saved text), audience and lead/ask to the configured text model. Its only style choices are compact/spaced layout and “For review:” or “Update:”, or no framing. It cannot turn “Ten users” into “Twenty users”, add an external audit, remove an attribution or rewrite claims. The deterministic renderer preserves each selected field completely.

Schema version 1: 10 briefs, 20 facts and 5 audiences per brief, at most 20 required links per audience. Names/titles <=160 UTF-8 bytes; other text <=1000. New content <=32768 bytes, state <=49152, export including envelope <=24576. Admission projects every record at maximum revision; rendering has no persisted completion payload. Optional text and requirement links are new content. No eviction, expiry, private cache or background work. Valid legacy state above byte caps stays inspectable/deletable.

Pipe parsing uses `\|`/`\\`; unknown/trailing escapes and extra separators reject. Delimiter-adjacent whitespace is trimmed; accepted interiors are retained. Plaintext output avoids double escaping. Lists use stable insertion order/ten roots; detail and variant pages retain complete identifiers and fields, display the revision, and require restarting page 1 after edits. Export is the bounded complete-JSON exception to normal 3500-unit replies.

Catalog budgets generations/searches/contextReads/storeReads/storeUpdates = 1/0/0/8/4. No context sources are read. Deterministic reads use one state read; mutations bind intent with one read before one update; polish uses one generation, up to two reads and zero writes. Model input <=16000 UTF-8 bytes, instructions <=4000, output <=4000 JS units, suggested section <=1000 bytes and full displayed response <=3500 units. No provider token ceiling exists in this API.

Pure synchronous transforms validate current schema, references and quota on every CAS retry. IDs/time are allocated outside them. Bad input, malformed state and failed optional output preserve bytes. Post-generation revision/signal checks discard results after edits/deletion. Runtime ownership, receipts and the original deadline apply; cancellation cannot undo an already dispatched CAS.

`tests/agent-audience-brief.test.ts` covers the exact first example/workflow, exact fact preservation, required overflow, audience selection/coverage, full editing/removal, maximum final fact/audience retrieval, Unicode quota recovery, optional references/quotes/word-budget checks, stale output and a genuine CAS conflict deleting a referenced fact. It uses the real runtime/scoped store and fake providers. Parent owns lazy registration, independent review and rollout.

Every mutation binds the intended record snapshot before CAS retries. A same-record change rejects the older command with an inspect/retry message, including status, evidence, attempts and confirmed deletion. Unrelated-record conflicts retry safely; a deleted target is never recreated.

Persisted enum fields require exact strings: arrays, nested arrays and coercible objects are malformed. Reads, rendering, edits and even confirmed deletion preserve corrupt raw bytes for scoped recovery.

Every saved-record and derived-report continuation includes `PAGE rev REV`. Copy the whole emitted command: REV combines the record revision with a content stamp, including at the revision ceiling. A mismatch rejects before rendering and gives a fresh page-1 command. Existing first-page commands and manually entered page numbers still render the current record; root lists are recomputed. No unsaved model output uses pagination.

Optional polish is constrained composition, with no free prose rewriting. The provider returns every known source exactly once, with exact full quotes and text equal to those quotes. The renderer copies saved bytes under fixed role labels and in fixed source order; provider ordering cannot reclassify evidence, relax a constraint or move an attribution. All supplied sections are mandatory in the composition. Unknown or duplicate source/framing IDs, omitted sections, added keys, changed quotes/text, appended factual claims and unsupported structures reject the entire result. The only presentation choices are compact/spaced layout and zero or one allowlisted nonfactual framing phrase. Entered claims remain user supplied and unverified; exact preservation is not truth verification.

The smallest complete composition is checked before generation; if required exact text cannot fit the 3500-unit reply or 4000-unit raw-output representation, the command refuses with a deterministic-page/edit-input action and makes no call. Accepted results remain unsaved, manual-review text. Full output is rechecked after generation; it fits completely or rejects, never truncates, silently drops content or paginates inaccessible model output. There is one explicit optional call and no repair call. Post-generation validation is not an upstream billing cap: the service interface still exposes no provider token ceiling. A final revision/content-stamp check discards stale output even after removals at the revision ceiling.
