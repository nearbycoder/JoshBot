# Energy pattern review

Implemented and registered; [release/deployment status is tracked in PR #59](https://github.com/nearbycoder/JoshBot/pull/59). See the [grouped guide index](README.md#find-a-feature) and [implementation/evidence record](../personal-agent-50-release.md).

Record explicit energy with `/nobo-help agent energy-patterns checkin 2026-10-22 | morning | 4 | writing | Felt alert`. Prefix the following commands with `/nobo-help agent energy-patterns` and use returned full IDs.

- `checkin DATE | morning/afternoon/evening | ENERGY | ACTIVITY | NOTE`; energy must be a literal integer 1–5. Dates are civil labels. Activity/note may be empty.
- `edit CHECKIN | DATE | BAND | ENERGY | ACTIVITY | NOTE` replaces every field. `note CHECKIN | TEXT` replaces context. `clear CHECKIN date/band/energy/activity/note confirm` removes the named field; incomplete measurements are excluded from patterns.
- `patterns START | END` describes an inclusive range. Each band and activity group needs three samples before median/range/sample dates appear. Sparse groups remain explicitly sparse. Missing days are unobserved, never zero; no health, sleep or causal claims are made.
- `journals DATE` discovers owned journal sources for the literal metadata day, returning stable IDs and current fingerprints. `journal SOURCE_ID` retrieves complete current source text/metadata through lossless pages. Both make one fresh journal-kind read.
- `attach CHECKIN | SOURCE_ID | FINGERPRINT | EXACT_EXCERPT` reads journal once and checks the displayed source fingerprint and literal excerpt against current text. It saves at most 400 JS units with original day, mood, selected-excerpt coverage, update/creation times when present, and toolbox provenance. The mood is context, never an energy score. Reissue attach for the same source to replace the saved snapshot; `detach CHECKIN ATTACHMENT_ID confirm` removes it. Missing/changed sources require rediscovery; old snapshots remain historical observations, without claiming current verification.
- `help`; `list [page N]`; `show CHECKIN [page N rev R stamp HASH]`; `export CHECKIN`; `delete CHECKIN confirm`.

Copy emitted `page N rev R stamp HASH` continuations exactly. Check-in pages bind the record; patterns bind the complete contributing state; journal pages reread sources once and check source fingerprints. Changed content rejects a continuation before rendering or source lookup. Root lists may recompute and display ten rows in date/ID order. Pipe/backslash literals use `\|` / `\\`. Export returns complete JSON with every accepted field and selected evidence.

Version 1 strict schemas preserve malformed states, exact enums, canonical IDs and invalid evidence rather than resetting them. `captureEvidence` validates complete source records and fingerprints meaningful metadata; selected excerpt snapshots retain selected fields and provenance. No direct sibling namespace read occurs: the injected caller-owned production services supply journal context. Each attachment captures its intended check-in before the asynchronous source read and revalidates every CAS retry. Later edit/deletion wins; unrelated changes may retry. Abort prevents late source results from saving.

Limits: 90 check-ins; 10 selected excerpts across all check-ins; aggregate title/excerpt text 8000 UTF-8 bytes; activity 80 and note 240 bytes. Source reads accept at most 100 adapter items; selection does not evade complete-read limits. Source failures direct users to `/nobo-help tools journal list`, preserve saved state and never masquerade as no data. State admission is 32768 bytes, hard cap 49152, complete export 24576, commands 16000 and normal replies 3500 JS units. Admission projects revision growth and each admitted source slot's worst-case replacement title/excerpt/metadata; optional new notes/selections use new-content admission. Limits may be reached by bytes first. Use show/export and confirmed removal to free space.

Budgets: zero generation/search, at most one journal read per explicit source invocation, eight logical state reads and four updates. No global private cache, background jobs, source writes, expiry or eviction.

Fake backing storage only; no live provider, Slack, Redis or deployment claim.

Revisions have a finite maximum of 9007199254740991. At that value, a record accepts only explicit erasure; an exhausted collection revision blocks all non-removal writes, including creation. One exhausted record does not block edits to other records when the collection has revision room. Known exhaustion rejects before source work and is checked again on every CAS retry. Inspection, saved reports and export remain available. Export before explicit field/child removal or `delete ID confirm`; those commands retain exact intended-record guards and may saturate revisions. This is a permanent finite limit, not a transient retry or corrupt-state error; deletion does not reset the collection revision.

Confirmed `delete ID confirm` also recovers a schema-valid legacy collection above 49152 bytes, within the shared store's 512000-byte readable ceiling. It validates the entire old and new state, binds the exact intended record on every CAS attempt, strictly reduces serialized bytes and cannot grow surviving lifecycle reservations. Surviving records and source snapshots are unchanged; repeated deletion can reach empty. Malformed data stays untouched. This exception applies only to deleting a whole record: create/edit, field or child removal and lifecycle admission checks retain their existing limits. No automatic reset, eviction or truncation occurs.
