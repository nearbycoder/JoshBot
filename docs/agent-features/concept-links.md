# Concept connections

Implemented locally, **unregistered and not deployed**; integration and independent review belong to the parent. This feature saves a directed concept graph with explicit `supports`, `contrasts`, `example`, and `depends-on` labels. Breadth-first traversal returns a shortest path, explains each user label, and uses saved insertion order to break ties. It expands each node once; cycles, shared nodes, self-links and disconnected concepts are safe. No edge implies causality or verified evidence.

Start `/nobo-help agent concept-links create Reliable systems`, then `concept MAP add Idempotency | Repeating a request does not add effects`. Add another node and use `connect MAP FROM | depends-on | TO | Avoid duplicate effects`, followed by `path MAP FROM | TO`. `edit`, `concept ... edit`, and `connect-edit` replace all accepted fields. `remove MAP concept|edge|attachment CHILD_ID confirm` removes explicit items; removing a concept removes its incident edges and attached snapshots. The static help specifies every command and pipe/backslash escaping.

Optional `sources MAP [--kind note|memory] [QUERY]` reads one complete permitted snapshot of at most 200 adapter items. Queries filter locally; kind narrowing is explicit. Sources list full IDs/fingerprints and labeled title/text previews. `sources MAP --kind KIND --source SOURCE_ID` retrieves complete adapter material in bounded pages. Source continuations bind both map revision and source-set fingerprint. A changed source or map requires page 1. All source strings are data; URLs are never fetched.

`attach MAP NODE | KIND | SOURCE_ID | SOURCE_FINGERPRINT | MAP_REVISION | EXACT_EXCERPT` fresh-reads that kind once, validates the current fingerprint and exact nonempty span, then saves a historical excerpt. `attach-edit MAP ATTACHMENT | NODE | KIND | SOURCE_ID | SOURCE_FINGERPRINT | MAP_REVISION | EXACT_EXCERPT` explicitly replaces it. Each attachment retains exact reference, source dates/status/URL, adapter coverage/truncation, and selected meaningful metadata through shared `captureEvidence`. Metadata includes toolbox source/creation and memory subject/key/card/revision/confirmation/expiry/confidence/origin. Observation-only metadata is excluded by the shared helper. Local capture time is separate. No source is made into an edge automatically.

Only sources and attach/attach-edit read context, at most once per invocation. `show`, `path`, and `export` label snapshots as historical/unverified. A later sources command reports unchanged-within-coverage, stale, outside requested scope, or absent/unavailable in the permitted snapshot; absence is not global deletion. Approved memory eligibility and workspace/owner checks remain enforced by the production adapters. The consumer additionally validates the exact toolbox-note or approved-memory reference/provenance contract and refuses mislabeled foreign adapter kinds. Arbitrary channel/workspace/artifact input and other agent stores are unsupported.

`list [page N]`, `show MAP [page N rev R]`, `export MAP`, and `delete MAP confirm` cover retrieval and cleanup. Saved and path pages bind the exact revision. Copy emitted continuation commands; all fields, including source metadata and long URLs, remain accessible. Export is complete JSON including its envelope, at most 24,576 UTF-8 bytes.

Strict schema version 1 and canonical UUIDv4 IDs; maximum 8 maps, 40 nodes, 80 edges and 10 selected excerpts per map. Titles are 160 bytes, annotations 600, edge labels 400; each selected excerpt is at most 600 JavaScript units/2,400 UTF-8 bytes, with 12,000 selected text bytes total. State is capped at 49,152 serialized bytes; content admission at 32,768. Optional annotations and snapshots are new content; remaining mandatory lifecycle is maximum revision width. Every mutation checks actual bytes and future state/envelope size inside every CAS retry. Confirmed removals retain hard and remaining-lifecycle guarantees beyond the content threshold. No expiry, eviction or history is added.

Every target revision is captured before mutation/source work and rechecked on every CAS retry. Same-record conflict rejects; unrelated changes retry. Per-invocation budgets are zero generation/search, one context read, eight state reads/four updates, and the store's independent 32 CAS attempts. Tests use actual runtime/store and production services/adapters with fake backend, including 100 real-schema notes plus 100 approved memory cards, complete pages, staleness/ownership revocation and real memory correction/unconfirmation, ten-source replacement/removal and byte quota rejection, directed graph oracles, corrupt-byte preservation, tenant isolation, and conflicting writes. No live inference, Slack, Redis or deployment was exercised.

A readable, fully schema-valid legacy aggregate can exceed current admission quotas. Confirmed whole-root deletion checks the exact intended record on every CAS retry and removes only that root; repeated deletion recovers space even while remaining roots exceed quota. Remaining records and their independent lifecycle reservations are unchanged. Creation, editing, child removal and lifecycle updates keep their existing quota checks. Malformed data is preserved for scoped operator recovery, never reset or evicted. Tests simulate legacy aggregates by cloning real-command roots with unique IDs; normal admission does not create those fixtures.
