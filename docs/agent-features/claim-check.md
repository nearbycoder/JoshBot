# Draft claim check

Implemented locally; **unregistered and not deployed**. Parent integration must register its metadata and lazy module. Prefix the following commands with `/nobo-help agent claim-check`; static `help` contains all syntax.

Start with `create Pilot announcement | Ten users completed onboarding in two minutes.` Copy the returned document ID and run `claim DOC add Ten users completed onboarding in two minutes.`, then `evidence DOC add Pilot notes | Ten users completed onboarding. Median time was four minutes.` Find the claim and evidence IDs with `show DOC`; `map DOC CLAIM | EVIDENCE | unclear` records your judgment. `audit DOC` exposes the missing numeric word `two`, the unclear mapping and the unknown evidence date. This is supplied-excerpt coverage, **not factual certification**. No source is verified, searched, fetched or declared trustworthy.

Claims must be exact current substrings. Repeated text needs `claim DOC add-at OFFSET | quote`; offsets are zero-based UTF-16 and ends are exclusive. `claim DOC edit CLAIM | quote` or `claim DOC edit-at CLAIM | OFFSET | quote` replaces/re-anchors the claim and clears its mappings. `revise DOC | source` preserves old claim quotations and offsets as visibly **stale**, even if the same words remain. Stale claims cannot be mapped until explicitly re-anchored. `title DOC | title` edits the title. Source and claim content is always retrievable.

`evidence DOC edit EVIDENCE | label | exact excerpt` edits either field. `date DOC EVIDENCE | YYYY-MM-DD` sets/corrects the user-supplied civil date; `remove DOC date EVIDENCE confirm` clears it. Dates are not inferred from ingestion time and their age does not prove truth or falsehood. Any evidence/date change makes old mappings visibly stale until explicitly mapped again. `map` accepts only `support`, `contradict` or `unclear`, replaces an existing claim/evidence pair, and requires existing owned IDs. Multiple linked excerpts are allowed; the audit separates contradictory user labels, unclear mappings and unmapped claims.

Numeric hints compare literal signed digit/decimal/percent tokens and English number words zero through nineteen, tens, hundred/thousand/million/billion. They do not add quantities, convert units, interpret compound words as a single number or establish whether a claim is false. Inspect both quotations before revising. `unmap DOC CLAIM EVIDENCE confirm` removes one mapping. `remove DOC claim|evidence CHILD confirm` removes the selected child and its mappings. Choose one kind in the syntax, rather than typing both alternatives.

`suggest-claims DOC` sends only the explicit draft to the configured model once. At most ten **unsaved proposals** must have exact current spans, offsets and bounded fields. Manually add selected proposals with `claim ... add-at`, then map evidence. Instructions treat source text as untrusted data. No result is auto-saved or executed. A concurrent edit/deletion discards proposals. Input is at most 16,000 UTF-8 bytes, instructions at most 4,000 bytes, raw accepted output at most 4,000 characters and each quote at most 240 units. The entire response must also fit 3,500 units; otherwise the whole result is rejected, never truncated or regenerated behind pagination. Failure leaves deterministic commands and saved data intact, with no retry/repair call. These are post-generation output checks; the existing API has no upstream token/billing cap.

`list [page]` shows all six possible roots and usage. `show DOC [page N] [rev N]` includes the entire source, every stale/current claim, evidence/date and mapping; `audit` accepts the same page suffix. Returned continuation commands bind to the current revision. `export DOC` is exact complete JSON with feature/version envelope and at most 24,576 UTF-8 bytes. `delete DOC confirm` deletes the root and every child; without confirmation it only returns the confirmation command. Pipe fields trim outer whitespace and decode `\|`/`\\`, with no double mrkdwn escaping in plain slash output.

State is strict version 1 in the sole `state` key. Limits are six drafts, 6,000 source units, twelve claims, twelve excerpts of 600 units, and at most 144 unique claim/evidence pairs, all subject to serialized UTF-8 quotas. New content fits 49,152 bytes; total state fits 65,536 bytes; each complete exported root fits 24,576 bytes. Admission reserves maximum revision widths, all evidence date fields, and one mapping for each unmapped claim, using the longest status. Extra evidence mappings are optional new content; first mappings, remapping existing pairs and dates use the lifecycle reserve and verify the remaining projection. Full rendering is checked at admission. At quota, inspect/export/delete to make space; nothing expires or is evicted. Invalid shapes, dates, offsets and relationships preserve raw state even on deletion; a maintainer must repair the scoped state. Help stays available.

CAS transforms are synchronous, validate full state and observed revisions on every retry, and never call services or create random IDs. Owner isolation, receipts, inherited cancellation and deadline come from the actual shared runtime/store. Cancellation cannot roll back an already dispatched CAS; inspect uncertain saves before repeating. Budgets match the catalog: one optional generation, zero searches/context calls, eight reads and four updates. Normal operations use one read and at most one update; suggestions use two reads and one generation. No external actions or background work.

Verification: seven tests in `tests/agent-claim-check.test.ts` through the real runtime/scoped-store fixture cover the catalog, signs/words, exact/repeated Unicode spans, all edits/removals, evidence invalidation, model rejection/edit/delete races, full retrieval, near-quota reserved completion, corrupt state, owner isolation and CAS contention. Run `node --import tsx --test tests/agent-claim-check.test.ts`, project `tsc --noEmit`, and `git diff --check`. Fake-backed local tests do not certify live Slack delivery or model quality.
