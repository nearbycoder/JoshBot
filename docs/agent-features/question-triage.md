# Open question triage

Implemented locally, **unregistered and not deployed**. Parent integration and independent review remain required. This private board connects questions to a decision, distinguishes blocking and optional uncertainty, and records explicit acceptable evidence, user answers, source labels, civil review dates and challenges. There is no research, generation or source fetching.

Start `/nobo-help agent question-triage create Choose workshop format`, then `ask BOARD add Can attendees install the software? | blocking | Determines whether live exercises are feasible`. Add `evidence-needed BOARD QUESTION | A pilot with three representative attendees`, inspect `queue BOARD`, record `answer BOARD QUESTION | All three installed it | Pilot notes | 2026-10-24`, and challenge with `challenge BOARD QUESTION | One pilot used a different operating system`.

Blocking unanswered/challenged/stale/missing-criterion questions lead the queue. Dated reviews follow, earliest first, then optional uncertainty and answered questions without dates. Unknown review dates remain unknown. Answers without acceptable evidence remain unresolved. All answers are user reports; no criterion certifies factual truth. Challenges preserve the prior answer/source. Changing decision, question, consequence or criterion marks affected answers stale. `answer-edit` explicitly replaces/reaffirms an answer but retains challenges until individually removed.

Help gives exact complete syntax. `edit`, `ask ... edit`, `evidence-needed`, `answer-edit`, and `challenge-edit` edit every input. `remove BOARD question|evidence|answer|challenge CHILD_ID confirm` removes explicit items; evidence/answer removal uses the question ID, challenge removal its own ID. Removing a question removes its owned answer/challenges. `list [page N]` returns ten-root pages, `show BOARD [page N rev R]` exposes all state, `export BOARD` returns complete envelope JSON, and `delete BOARD confirm` removes the root. Queue continuations bind both revision and original civil as-of date; show binds revision. Copy emitted commands; changed state requires page 1.

Schema version 1 uses canonical UUIDv4 IDs and strict enums, booleans, dates and nested fields. Maximum 12 boards, 24 questions each, one answer and three challenge notes per question. Decision 160 UTF-8 bytes, question 320, consequence/criterion/answer 256, source label/challenge 128. State is 49,152 bytes, content admission 32,768, complete export 24,576 including envelope. Admission projects a maximum escaped answer/source/review date and all three challenges for every accepted question, plus revision width. This strong reservation can bind well before count limits, even for initially short questions. Wording/criterion additions are new content; answers/challenges and confirmed removals retain hard and remaining-lifecycle guarantees above content admission. No automatic expiry, eviction, hidden history or cache.

All mutation targets capture their revision before entering CAS and recheck every retry, including answer, challenge, criterion and removal. Unrelated-board conflicts retry safely; same-board conflicts require inspection and retry. Corrupt saved state stays byte-for-byte intact, including confirmed delete. Per invocation: zero model/search/context, eight state reads/four updates; internal CAS has its separate 32-attempt limit. Queue work is bounded by the question count.

Tests use actual runtime/store fixtures for the full catalog flow, ordering and stale evidence, leap/unknown dates, complete revision/as-of pages, owner/workspace isolation, actual CAS conflicts, malformed enums/raw bytes, and near-quota Unicode/escaping through every admitted answer/challenge and removal. Run `node --import tsx --test --test-concurrency=1 tests/agent-question-triage.test.ts` with Node 24. These local tests do not establish Slack delivery or production rollout.

A readable, fully schema-valid legacy aggregate can exceed current admission quotas. Confirmed whole-root deletion checks the exact intended record on every CAS retry and removes only that root; repeated deletion recovers space even while remaining roots exceed quota. Remaining records and their independent lifecycle reservations are unchanged. Creation, editing, child removal and lifecycle updates keep their existing quota checks. Malformed data is preserved for scoped operator recovery, never reset or evicted. Tests simulate legacy aggregates by cloning real-command roots with unique IDs; normal admission does not create those fixtures.
