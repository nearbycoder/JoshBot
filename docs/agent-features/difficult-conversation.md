# Conversation rehearsal

Privately prepare a goal, opening, nonnegotiable boundary, acceptable concessions and an explicit stop condition, then practice one objection at a time. Practice hides your prepared response; after you record an attempt, review reveals it alongside your attempt and a boundary checklist. The tool does not contact anyone, predict a real person's words or conduct a continuous conversation.

Start: `/nobo-help agent difficult-conversation create Discuss shifting the deadline | Agree on a feasible scope`. Replace `ID`, `CARD` and `ATTEMPT` with returned IDs. Commands follow `/nobo-help agent difficult-conversation`:

- `opening ID | TEXT`, `boundary ID | TEXT`, `concession ID | TEXT`, `stop ID | TEXT` record explicit preparation. Missing concessions/capacity are not inferred.
- `edit ID | title/goal/opening/boundary/concession/stop | TEXT`, `clear ID FIELD confirm` replace/remove preparation fields and clear active practice. Retained attempts are preserved and reviewed against clearly labeled current preparation.
- `objection ID add OBJECTION | PREPARED-RESPONSE` adds a stable card and reserves both bounded attempt slots. `objection ID edit CARD | OBJECTION | PREPARED-RESPONSE` replaces it only after any retained attempts are explicitly removed, preventing attempts from being relabeled against a changed question/answer. `objection ID remove CARD confirm` removes the card and its attempts.
- `prepare ID [page [rev REV]]` shows preparation, stop conditions and available cards without revealing prepared responses. `practice ID CARD` starts one explicit turn and returns only the goal, objection and response-entry guidance. It refuses if another card is active or both slots are occupied.
- `respond ID | TEXT` saves one response of at most 320 UTF-8 bytes to the active card, ends the turn, and returns an exact review command. It binds to the active revision: a concurrent cancel/change cannot attach it elsewhere.
- `review ID CARD [page [rev REV]]` reveals the prepared response after at least one attempt and provides the current boundary/concession/stop checklist. `cancel ID confirm` clears the active turn while preserving all saved attempts.
- `attempt ID CARD edit ATTEMPT | TEXT` replaces an attempt within its reserved 320-byte slot and clears its self-rating. `attempt ID CARD remove ATTEMPT confirm` removes it. Both clear active practice.
- `rate ID CARD ATTEMPT | 1-5` records your subjective self-rating; `unrate ID CARD ATTEMPT confirm` clears it. No objective skill score is inferred.
- `simulate ID | OBJECTION` requests one unsaved hypothetical response based on the supplied scenario. It neither starts practice nor saves cards/attempts, and never starts a follow-up call. The response is labeled hypothetical, not attributed to a real person.
- `list [page]`, `show ID [page [rev REV]]`, `export ID`, `delete ID confirm` expose/remove all retained input, IDs, attempts, ratings and timestamps. Show/export deliberately include prepared responses; practice hiding is an exercise, not an authorization barrier. Delete without confirmation displays its exact confirmation command.

Pipe grammar supports `\|` and `\\`; unsupported/trailing escapes or extra separators reject. Delimiter-adjacent whitespace is trimmed; accepted interior text is preserved. Recipients, mentions and URLs are plaintext.

Schema version 1 permits 12 sessions, 12 objection cards each and 2 retained attempts per card, without automatic eviction. Topic/title <=160 UTF-8 bytes, other preparation/card text <=1000, attempts <=320. New content <=32768 bytes; full state <=49152; each complete export envelope <=24576. Byte limits can reject before count limits.

Mandatory lifecycle admission projects **two maximum-size attempts on every admitted card**, maximum revision digits, full fixed-width timestamps/IDs, and `null` self-ratings (the longest allowed rating value). The projected attempt text uses 320 quote characters, each requiring two serialized JSON units. All-completed cards with a null active pointer exceed the size of any one active-card ID with a still-missing response slot; this proves practice/respond/rating capacity rather than treating the 16384-byte margin as proof. The projection is schema validated and checked against full-state and envelope limits inside each content CAS transform. Practice, responses, bounded attempt revisions and ratings use that reserved space. Optional preparation and card text require fresh content admission. No generated history is retained.

Normal responses/pages stay within 3500 JS units; full export is the explicit bounded exception. List uses insertion order/ten roots; show/review/prepare retain complete fields and IDs and label the current revision. Restart page 1 after edits. Fully valid legacy data remains inspectable/deletable over byte admission caps.

Catalog budgets generations/searches/contextReads/storeReads/storeUpdates = 1/0/0/8/4. Deterministic operations perform one read or one update, except respond uses a read plus one revision-guarded update. Sources are entered data only. Simulation uses one generation, up to two state reads, no writes, input <=16000 UTF-8 bytes, instructions <=4000, raw output <=4000 JS units, section text <=1000 UTF-8 bytes, complete response <=3500 units. Known references/exact quotes and an explicit objection reference are required; unknown keys or excessive output reject with a useful preparation command. No repair calls, generated pagination, provider-token-cap claim or timers.

Schema/quotas are validated on every loaded state/change; transforms are synchronous and IDs/time are allocated outside them. Optional results reread revision and signal, so edits/deletion discard late output. Original runtime receipts, owner isolation and deadline apply. Cancellation cannot roll back a CAS already dispatched. Invalid input/state or failed optional output never resets saved records.

`tests/agent-difficult-conversation.test.ts` covers the exact catalog workflow, hidden answer, active-turn enforcement, stop/boundary preparation, ratings, all field/card/attempt edits/removal, final card/attempt retrieval, Unicode, and a near-capacity completion with maximum JSON-escaped attempts. It also forces a CAS conflict changing the active card and tests optional malformed/stale/cancelled output through the real runtime/scoped store. Parent owns registration, independent review and deployment; local fake-backed tests do not approve release.

Every mutation binds the intended record snapshot before CAS retries. A same-record change rejects the older command with an inspect/retry message, including status, evidence, attempts and confirmed deletion. Unrelated-record conflicts retry safely; a deleted target is never recreated.

Every saved-record and derived-report continuation includes `PAGE rev REV`. Copy the whole emitted command: REV combines the record revision with a content stamp, including at the revision ceiling. A mismatch rejects before rendering and gives a fresh page-1 command. Existing first-page commands and manually entered page numbers still render the current record; root lists are recomputed. No unsaved model output uses pagination.
