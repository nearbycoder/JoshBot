# Document critic

Implemented locally; **unregistered and not deployed**. The parent must add the metadata and lazy module to discovery. After integration, prefix commands with `/nobo-help agent document-critic`. `help` is static and lists the complete grammar.

Create a brief with `create Setup guide | New users | Help a new user install the app`, copy its full document ID, then `text DOC | # Install\nRun the installer.` (paste actual newlines). Use `require DOC | Install,Verify,Troubleshooting`, `check DOC`, and `revise DOC | corrected text`. Missing exact Markdown heading labels, paragraphs over 120 whitespace-delimited words, and unexplained **user-listed** acronyms are explicit heuristics, never correctness scores. `lines DOC` numbers every current line; paragraphs end at blank lines. Columns count UTF-16 units, not visual graphemes.

`rubric DOC add criterion` creates an identified rule; `rubric DOC edit RULE | criterion` replaces it. `acronym DOC add TERM | expansion` and `acronym DOC edit ACRONYM | TERM | expansion` manage up to twenty uppercase terms. An empty expansion means unknown. The expansion check recognizes the literal forms `expansion (TERM)` and `TERM (expansion)`. Unlisted acronyms are not guessed. `show DOC` exposes full rule/acronym IDs.

`mark DOC RULE | startLine | endLine | exact quote | opinion` adds or replaces one user finding for that rule. The line range must match exactly the lines touched by the quote; quotes and line numbers are validated against the current text. Text, brief, and heading edits invalidate all findings; editing/removing a rule invalidates its finding. Every remaining finding is explicitly tied to the current revision. `edit DOC title|audience|purpose | value` edits one selected brief field. `remove DOC rubric|acronym|mark CHILD confirm` removes a selected item (mark uses the rule ID); `clear DOC text|headings confirm` clears the selected field. The notation `title|audience|purpose` means choose one word, not enter all three.

`critique DOC` explicitly sends the supplied brief, text, and rubric to the configured text model once. It returns at most eight **unsaved model opinions**, with validated rule IDs, exact quotes and current line ranges. Review and copy selected findings into `mark`; there is no automatic apply. Instructions treat source material as data. Any edit/deletion during generation discards the result. Provider failures and invalid/oversized results leave all saved data untouched. The accepted response is complete within 3,500 units; results are never clipped or fake-paginated through a second generation. Inputs are at most 16,000 UTF-8 bytes, instructions at most 4,000 bytes and accepted raw outputs at most 4,000 characters (quotes 240 units, notes 160 units, plus the complete-reply check). This validation happens **after generation**; the existing API cannot impose an upstream output-token or billing ceiling.

`list [page]` lists all six possible roots and state usage. `show DOC [page N] [rev N]` exposes every field; `lines` and `check` use the same page syntax. Follow the exact next command; revision-bound continuation rejects changed data. `export DOC` returns the complete JSON envelope, at most 24,576 UTF-8 bytes. `delete DOC confirm` removes the document and all owned data; the unconfirmed command displays the confirmation command. No automatic expiry, eviction or hidden history exists. Pipe fields trim outer whitespace and decode `\|` and `\\`; accepted source text is otherwise preserved, including newlines. Plain slash replies are not pre-escaped as mrkdwn.

The sole `state` value is a strict version-1 schema: six documents, 6,000 source units each, twelve headings, rubric rules and user findings per document, twenty acronym entries. Actual serialized UTF-8 limits (including JSON escaping) can fill before counts: 49,152 new-content bytes, 65,536 total bytes, and 24,576 per exported root. Admission projects maximum-safe revision widths for all records/anchors and verifies complete renderability. Findings are optional new content, not promised future generated storage. Quota rejection preserves state and names list/export/delete recovery. Malformed schemas/relationships are preserved, including on deletion; ask a maintainer to repair the scoped state rather than silently resetting it. All edits and removals revalidate the observed revision inside synchronous retry-safe CAS transforms; IDs are generated outside them.

No searches, context reads, external sends or background work. Metadata budgets are one optional generation, zero searches/context reads, eight logical reads and four updates; ordinary commands use one read and at most one update, critique two reads and one generation. The existing runtime supplies owner isolation, cancellation, deadlines and receipt deduplication. A CAS already dispatched at cancellation cannot be rolled back; inspect saved state before repeating an uncertain write.

Verification: `node --import tsx --test tests/agent-document-critic.test.ts` (seven domain tests using the real scoped store/runtime fixture and fake services), project `tsc --noEmit`, and `git diff --check`. Tests cover the catalog flow, rule boundaries, exact anchors and invalidation, optional response rejection/edit/delete races, Unicode/escaping/full pages, quotas, strict corruption handling, owner isolation and a real CAS conflict. These establish local contracts, not live Slack or model quality.
