# Evidence timeline

Implemented and registered; [release/deployment status is tracked in PR #59](https://github.com/nearbycoder/JoshBot/pull/59). See the [grouped guide index](README.md#find-a-feature) and [implementation/evidence record](../personal-agent-50-release.md).

This private deterministic feature arranges supplied observations in separate exact-instant, civil-label and unknown-date bands, with explicit before constraints and retained disputes. It neither fetches sources nor chooses a true account.

Start with `/nobo-help agent timeline-builder create Launch history`. Use the returned timeline ID in `entry TIMELINE add LABEL | DATE | SOURCE LABEL | EXACT EXCERPT`, then `before TIMELINE ENTRY | LATER_ENTRY` and `view TIMELINE`. `DATE` accepts a valid civil date, an explicit-offset instant, or `unknown`. Repeated dates remain distinct observations. Exact offsets remain available in export; civil dates never acquire timestamps. Mixed precision comparisons use conservative ±14-hour offset bounds; overlapping bounds do not prove ordering. Order cycles reject atomically.

`edit TIMELINE | TITLE` changes the title. `entry TIMELINE edit ENTRY | LABEL | DATE | SOURCE LABEL | EXACT EXCERPT` replaces observation fields and retains its dispute/order declarations for review. `before-edit TIMELINE ORDER | ENTRY | LATER_ENTRY` edits a constraint. `dispute TIMELINE ENTRY | NOTE` adds one replaceable note; `dispute-edit` edits it. `remove TIMELINE entry|order|dispute CHILD_ID confirm` removes the named item; entry removal also removes incident constraints and its dispute. Help contains exact syntax; escape literal pipes as `\|` and backslashes as `\\`.

`list [page N]` recomputes ten-root pages. `show TIMELINE [page N rev R]` retrieves every retained field; `view` pages the derived chronology. Copy exact continuations: they bind the originating revision and require page 1 after any change. `export TIMELINE` returns complete JSON, including an envelope, within 24,576 UTF-8 bytes. `delete TIMELINE confirm` removes the root and owned children. No eviction, expiry, history or global cache exists.

Schema version 1 uses canonical UUIDv4 IDs and strict dates/enums/fields. There are at most 12 timelines, 30 observations and 50 constraints each. Titles/labels are 160 bytes; source labels 200; excerpts 600; one dispute per observation is 256. State is capped at 49,152 serialized UTF-8 bytes; content admission at 32,768. Admission also projects maximum revision width and a worst-case escaped dispute for every accepted observation into both state and envelope bounds. Disputes and confirmed removals bypass the content threshold but retain hard and remaining-lifecycle guarantees. Bytes may limit counts first. Corrupt state is preserved even on confirmed delete. Whole-timeline deletion remains available at the maximum valid revision; other mutations require exporting/deleting that exhausted record.

Every mutation captures a revision before CAS and checks it on every retry. Same-record conflict rejects with inspect/retry guidance; unrelated-record changes retry safely. No generation, context or search calls; per invocation budgets are 8 store reads/4 updates, with the shared store's separate 32-attempt CAS limit. Graph validation is bounded Kahn traversal, and chronological sorting is bounded by 30 observations.

Validation uses the real runtime/store fixture: catalog flow, leap/offset/DST precision, cycles, full revision-bound pages, maximum counts, malformed-state byte preservation, tenant isolation, actual CAS conflicts, and Unicode/escaping near-quota dispute lifecycle and deletion. Run Node 24 with `node --import tsx --test --test-concurrency=1 tests/agent-timeline-builder.test.ts`; fake-backed checks establish no Slack delivery or production performance claims.

A readable, fully schema-valid legacy aggregate can exceed current admission quotas. Confirmed whole-root deletion checks the exact intended record on every CAS retry and removes only that root; repeated deletion recovers space even while remaining roots exceed quota. Remaining records and their independent lifecycle reservations are unchanged. Creation, editing, child removal and lifecycle updates keep their existing quota checks. Malformed data is preserved for scoped operator recovery, never reset or evicted. Tests simulate legacy aggregates by cloning real-command roots with unique IDs; normal admission does not create those fixtures.

Pure command, schema, quota, pagination and evidence validation failures keep their actionable guidance. Unexpected backend/provider diagnostics are never returned. A storage failure directs inspection before retry because a dispatched save might have completed; it does not promise rollback. Source-read failures preserve saved snapshots and retain typed capacity guidance. Cancellation, deadlines and runtime corruption/budget diagnoses remain runtime-owned.

Explicit removals remain available when only the root revision reaches its valid ceiling (999,999,999); that revision stays at the ceiling. Creation of children, edits and new lifecycle reports at that ceiling are refused. Every intended mutation is also bound to the complete record's content stamp, including every CAS retry. Unrelated records may change and retry safely. No stored fields, schema versions or budgets were added.

Start again with `show ID` if an old numeric-only continuation is rejected. Page 1 without a token remains available. Complete pages and exports retain their existing limits.
