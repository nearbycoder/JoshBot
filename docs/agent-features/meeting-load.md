# Meeting load review

Implemented locally; **not registered or deployed**. Parent integration owns registration, independent review and release.

Start `/nobo-help agent meeting-load create Workweek review | 2026-10-26 | 2026-10-30`. Prefix subsequent commands with `/nobo-help agent meeting-load`; replace `REPORT` with the returned full ID.

- `create TITLE | START | END` sets an inclusive range of 1–14 civil days between 1900 and 2200. Defaults are 09:00–17:00, minimum focus 60 minutes and recovery 10 minutes. The daily window includes weekends; it does not infer a workweek schedule.
- `settings REPORT | HH:MM-HH:MM | MIN_FOCUS | RECOVERY` replaces the work window and thresholds. Only the end may be 24:00. Focus is 1–1440 and recovery 0–1440 minutes.
- `range REPORT | START | END`; `edit REPORT title | TEXT`; `labels REPORT | BYTES` (0–80) edit the remaining fields. Labels are explicitly clipped previews; no source interval is removed to meet a text limit.
- `analyze REPORT` makes exactly one complete event-kind read and saves one compact report snapshot. Invalid intervals, unresolved flags/dates, incomplete coverage, DST gaps/folds and source-capacity errors fail visibly and preserve the last report.
- `report REPORT` computes from the saved intervals. `what-if REPORT recovery | MINUTES` changes only the hypothetical recovery target, with zero source reads or writes. Both show the capture instant, civil capture day, timezone, saved assumptions and current configuration. Changed configuration/timezone is labeled **STALE** until a new analysis; what-if retains captured assumptions.
- `clear REPORT title/range/settings/snapshot/labels confirm` removes the named field or snapshot; labels resets to 80. Restore required range/settings before analyzing.
- `help`; `list [page N]`; `show REPORT [page N rev R stamp HASH]`; `export REPORT`; `delete REPORT confirm`. Report/what-if also emit stamped continuations. Copy those commands exactly.

Busy minutes are the union of positive-duration busy intervals clipped to each work window, using half-open endpoints. Overlapping meetings count once. Transparent events and point events contribute no duration. Gaps are maximal uninterrupted free intervals; focus gaps meet the stated minimum duration. A day with no qualifying gap is labeled as missing the focus-gap target in this snapshot, without inferring calendar completeness.

Recovery pressure uses one boundary for each distinct clipped busy end. Available recovery runs from that end to the next busy start or work-window end; another ongoing busy interval gives zero. Deficit is `max(0, target − available)`. Coincident end boundaries count once; touching meetings and work-window ends are explicit. This is a disclosed descriptive measure, not an inferred physiological recovery requirement or causal productivity claim.

All-day original civil dates and exclusive ends are retained, and midnight conversion must match the caller's IANA timezone. DST uses real elapsed minutes: a complete spring-forward all-day interval is 1380 minutes and a fall-back day is 1500. Ambiguous/nonexistent work boundaries reject rather than invent an instant. Confirmed import coverage is not external/live calendar completeness. An empty import remains unverified, never a verified free calendar.

The production services read only the signed caller's calendar through the adapter. All up to 100 returned events survive the snapshot, including old events, transparent entries and points. `captureEvidence` validates every full source shape and preserves selected interval/flag/date/timezone metadata in the projection fingerprint; a separate full-source digest records the complete selected-source fingerprints. Compact tuples store calendar ID suffixes, exact epoch milliseconds, flags, source timezone dictionary index, label preview, update instant and original all-day dates. The complete export includes column definitions and the `calendar:cal_` prefix needed to reconstruct every canonical source ID. No source body text or arbitrary context kind is retained.

Version 1 strict schemas validate canonical IDs/timestamps, exact enum/flag types, coverage, date/time consistency, exact nine-column tuple shapes (extra or missing columns reject without changing saved bytes), counts and projection fingerprints before every write, including deletion. Mutation intent is captured before the source read and checked on every CAS retry. Later edit/deletion wins and unrelated records retry safely. Abort discards late source results. Detail pages bind record revision/content; derived pages also bind the caller timezone. All saved fields are accessible through lossless plain-text JSON pages or complete export. Literal pipes/backslashes use `\|` / `\\`.

Limits: 8 configurations, 14 civil days/report, 100 source references and 8000 label-text bytes; one snapshot per configuration. Each snapshot is at most 22000 serialized UTF-8 bytes. State admission is 32768, hard cap 49152, complete record export 24576, commands 16000 bytes, normal replies 3500 JS units. Once admitted, each snapshot slot reserves its full 22000-byte replacement capacity plus configuration/revision growth. This can limit saved reports before eight configurations; configuration creation and first capture are new content. Existing replacements, required settings/ranges and removal remain available at accepted capacity. Source-size recovery uses `labels REPORT | 0` or explicit cleanup in `/nobo-help agent calendar list`; local report cleanup cannot shrink an upstream calendar. No silent interval truncation, eviction, expiry, cache or background work occurs.

Budgets: zero generation/search; one event read only on analyze; eight logical state reads/four updates. `node --import tsx --test --test-concurrency=1 tests/agent-meeting-load.test.ts` covers actual confirmed ICS imports through production services/adapters and runtime, independent overlap/touching/clipping/point oracles, all-day exclusive ends, DST arithmetic/failures, all 100 events, strict source/state preservation, deferred cancellation/deletion, real CAS races, stamped retrieval and saturated snapshot replacement/removal. Fake storage only; no live Slack, Redis, provider or deployment claim.

Revisions have a finite maximum of 9007199254740991. At that value, a record accepts only explicit erasure; an exhausted collection revision blocks all non-removal writes, including creation. One exhausted record does not block edits to other records when the collection has revision room. Known exhaustion rejects before source work and is checked again on every CAS retry. Inspection, saved reports and export remain available. Export before explicit field/child removal or `delete ID confirm`; those commands retain exact intended-record guards and may saturate revisions. This is a permanent finite limit, not a transient retry or corrupt-state error; deletion does not reset the collection revision.
