# Text change digest

Implemented and registered; [release/deployment status is tracked in PR #59](https://github.com/nearbycoder/JoshBot/pull/59). See the [grouped guide index](README.md#find-a-feature) and [implementation/evidence record](../personal-agent-50-release.md).

Prefix commands with `/nobo-help agent change-digest`; static `help` documents the complete grammar.

`create Launch note | before | Launch on October 30 with 10 users.` saves a named before version. Copy the comparison ID into `after DIFF | Launch on November 6 with 20 users.` and `compare DIFF`. The report shows exact deleted/inserted spans, offsets, the change from `October 30` to `November 6`, and the numeric `10`/`20` change. Copy the full hunk ID into `classify DIFF HUNK | substantive | Launch date and audience changed`, then `digest DIFF`. Substantive, cosmetic and unreviewed hunks remain separate; no lexical heuristic silently marks a hunk reviewed.

`before DIFF | text`, `after DIFF | text`, `title DIFF | title` and `labels DIFF | before label | after label` edit all supplied fields. A missing after version differs from an explicitly supplied empty after (`after DIFF |`), which produces deletion-only comparisons. Every text/title/label edit increments the diff revision, changes hunk IDs and clears all previous classifications. Even an identical replacement invalidates old review context deliberately. Hunk IDs are `COMPARISON_UUID:rDIFF_REVISION:hINDEX`; they are stable across classification-only edits and include the full root identity. Old or foreign IDs cannot classify a new comparison.

`classify DIFF HUNK | substantive|cosmetic | rationale` chooses one category and replaces its existing category/rationale. Rationales are at most 96 UTF-8 bytes and can be empty. `unclassify DIFF HUNK confirm` removes that classification, making the hunk unreviewed. `clear DIFF before|after|classifications confirm` clears the selected field and invalidates old hunk IDs; clearing after restores the missing-after state. Choose a single alternative in syntax, rather than typing all words. `delete DIFF confirm` removes both versions/labels and every classification; unconfirmed delete only displays a confirmation command. No revision history, automatic eviction or expiry is retained.

Diffing uses a deterministic longest-common-subsequence table bounded by 120 lines per side: at most 121×121 unsigned 16-bit cells (29,282 bytes for the table), plus bounded tokens/offsets. A deletion-first tie break makes repeated lines deterministic. Tokens include their newline terminators, so all accepted source text can be reconstructed from exact hunk deletions/insertions without dropping repeated lines or Unicode. Contiguous changed runs form at most sixty hunks; a larger result rejects the entire write. Offsets count UTF-16 units, zero-based with exclusive ends; line starts are one-based. A trailing empty line counts toward the 120-line bound.

Changed token hints are literal signed numbers/decimals/percentages, ISO-shaped and English full-month date strings, and capitalized `name?` candidates. They retain exact old/new offsets and account for repeated token counts. They do not validate dates, interpret business meaning, equate units, certify truth or reliably identify proper names. A whitespace-only hint is likewise not an automatic cosmetic classification. Both sides and every unreviewed hunk remain inspectable.

`list [page]` shows all six possible comparisons and state usage. `compare DIFF [page N] [rev N]` includes all exact spans/hints; `digest` groups those complete hunks by review category, retaining their IDs and rationales. `show` exposes all saved fields with the same page suffix. Continuation commands contain full IDs/revisions and refuse changed records. `export DIFF` returns exact complete JSON (feature/version envelope plus before/after labels/text/revisions/classifications) within 24,576 UTF-8 bytes. Hunks are deterministically derived from those versions, not a duplicated retained source copy. Pipe fields trim outer whitespace and decode `\|`/`\\`; source content is otherwise preserved, and plain replies are not double escaped.

Strict version-1 state uses only the scoped `state` key: six comparisons, 6,000 units/16,000 bytes and 120 lines per side, sixty hunks/classifications. Serialized UTF-8 quotas include Unicode and JSON escaping: 49,152 new-content bytes, 65,536 total bytes, 24,576 per exported root. Admission reserves the longest classification, maximum-escaped 96-byte rationale and maximum-safe revision/hunk-ID widths for **every** hunk in **every** root. All mandatory classifications remain possible at capacity. Byte quotas may reject before nominal count/text limits; no partial diff is admitted. Complete show/compare/digest rendering is validated before admission. Quota recovery is list/export/confirmed deletion; malformed shapes, revision/hunk references or classifications are preserved even on deletion and require maintainer repair of that scoped state. Help remains available.

Synchronous retry-safe transforms validate full state and the observed root revision on every CAS attempt; random root IDs are created outside callbacks. Concurrent text edits/deletion prevent stale classifications from writing. The shared actual runtime supplies owner isolation, receipt deduplication, inherited cancellation and deadline. Cancellation cannot roll back an already dispatched CAS; inspect uncertain saved state before retrying. Metadata exactly declares zero generations/searches/context reads, eight logical reads and four updates; commands use one read and at most one update. There are no external sends, background tasks or provider calls.

Verification: eight tests in `tests/agent-change-digest.test.ts` through the real runtime/scoped-store fixture cover the catalog, reconstruction from repeated/Unicode/empty-side diffs, all field edits/invalidation, lexical signs/dates/names/whitespace, 120 lines and sixty fully classified hunks with maximum escaped rationales, 6,000-unit sources/full pages, near-quota completion, corrupt state/owner isolation and a real CAS edit conflict. Run `node --import tsx --test tests/agent-change-digest.test.ts`, project `tsc --noEmit`, and `git diff --check`. This is local evidence, not live Slack/deployment verification.

Clearing `before` uses lifecycle admission (65536-byte state and 24576-byte record caps), so valid classification growth above the 49152-byte new-content cap does not block erasure. An existing `after` can turn the remaining comparison into a full insertion; the command invalidates old classifications and reprojects every remaining hunk with its maximum escaped rationale and full revision width. Missing `after` creates no hunks. Clearing `after` or classifications and deleting records remain removal operations.
